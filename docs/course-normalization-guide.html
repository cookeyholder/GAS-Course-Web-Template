108 課綱課程代碼 1NF 正規化工程解析

解析巨耀等校務行政系統之 39 欄課綱寬表結構，透過第一正規化（1NF）數學展開、非授課屬性排除與字典快速映射，構建高效能標準課程資料庫。

1 為什麼需要 1NF（第一正規化）？

在台灣高中職校務系統（如巨耀資訊）匯出的 108 課綱課程代碼表中，為便於人工排版檢視，採用了多維度混合的橫向「寬表（Wide Table）」結構：

  • 單一資料列橫向包含了高一、高二、高三共六個學期的開課學分、時數與開課方式。
  • 欄位中同時包含了入學年、一年級學年、二年級學年、三年級學年。

這種寬表結構在資料庫檢索、排序與關聯時具有極大缺點：無法以單一條件篩選特定學期開課科目，必須寫複雜的多條件 OR 判斷。藉由第一正規化（1NF，First Normal Form）將六學期的重疊維度消除，轉為單一學期單一列的扁平化紀錄：

原始 39 欄寬表 1 列橫跨三年六學期
屬性過濾 即時剔除非授課 (0/6)
六學期展開 僅保留學分或時數 > 0
14 欄標準 1NF 單一學年/學期/年級索引

2 巨耀 39 欄原始寬表欄位剖析

原始檔案具備以下 39 個欄位（0-based 索引 0 至 38）：

欄位範圍欄位名稱代表意義與用途
0 ~ 4課程代碼、六學期開課學分、科目名稱、學生入學年、校代碼課程基本身分與入學年標識。
5 ~ 11課程類型、群別、科別、班群、課程類別、開課方式、科目屬性代碼化屬性（如群別 23、科別 305、屬性 3）。
12 ~ 15領域名稱、科目名稱代碼、科目代號、必選修教育部課綱編碼資訊。
16 ~ 18學生一、二、三年級學年計算各年級修課當時之實際開課學年度（如 114、115、116）。
19 ~ 24一上～三下開課學分（共 6 欄）各學期實際授予學分數（判斷當期是否有開課之主依據）。
25 ~ 30一上～三下開課時數（共 6 欄）各學期每週實際上課節數。
31 ~ 36一上～三下開課方式（共 6 欄）各學期個別開課方式（若為空則退回第 10 欄預設開課方式）。
37 ~ 38授課學期學分節數、課程屬性統計與備註欄位。

3 關鍵屬性過濾：剔除代碼 0 與 6 之依據

在解析課程代碼時，並非所有科目都屬於正式考試或排程範疇。在 subjectCodeTransformer.js 中定義了嚴格的排除條件：

subjectCodeTransformer.js
/** 匯入時應直接剔除的科目屬性代碼（L 欄，0-based index 11） */
const EXCLUDED_SUBJECT_ATTRIBUTES = ["0", "6"];

function isExcludedCourseRow(row) {
  if (!Array.isArray(row)) return true;
  const attr = row[11] === null || row[11] === undefined ? "" : String(row[11]).trim();
  return EXCLUDED_SUBJECT_ATTRIBUTES.indexOf(attr) !== -1;
}
屬性代碼屬性名稱排除原因
"0" 不分屬性 通常為週會、班會、社團活動或每週彈性學習時間，不授予正式學科成績，無考試或補考排程需求。
"6" 特殊需求領域 特教資源班或個別化教育計畫（IEP）之輔助課程，評量方式採個別化評量，不納入全校常規考程編排。

4 展開演算法與數學映射關係

單一列 39 欄資料會經由迴圈 s = 0 ~ 5 檢驗六個學期：

subjectCodeTransformer.js (expandCourseRow)
for (let s = 0; s < 6; s++) {
  const credits = Number(row[19 + s] || 0);
  const hours = Number(row[25 + s] || 0);

  // 1. 僅展開「學分 > 0 或時數 > 0」之實質開課學期
  if (!(credits > 0 || hours > 0)) continue;

  // 2. 年級索引 (0: 高一, 1: 高二, 2: 高三)
  const gradeIndex = Math.floor(s / 2);

  // 3. 開課學年：對應第 16 + gradeIndex 欄
  const academicYear = String(row[16 + gradeIndex] || "").trim();

  // 4. 開課學期：(s % 2) + 1 (1: 上學期, 2: 下學期)
  const semester = String((s % 2) + 1);

  // 5. 開課方式：優先取第 31 + s 欄，空值退回第 10 欄
  const semesterOpenWay = row[31 + s] || row[10];

  // 組裝 14 欄標準紀錄...
}

6 前後端同構運算設計 (Isomorphic Design)

傳統系統常在上傳檔案後整份丟給後端 GAS 運算，但 GAS 有單次請求時間與記憶體限制。本範本採用前後端同構設計：

  • 前端 ([courseData.js](file:///home/cookeyholder/Projects/GAS-Course-Web-Template/webapp/js/courseData.js))：使用 SheetJS 在用戶瀏覽器內完成解析與 1NF 展開，即時呈現「原始筆數」、「排除筆數」與「展開筆數」統計卡片，使用者確認無誤後才發送。
  • 後端 ([subjectCodeTransformer.js](file:///home/cookeyholder/Projects/GAS-Course-Web-Template/subjectCodeTransformer.js))：接收已預先展開之陣列，以每批 5000 筆快速寫入試算表，節省 90% 的後端運算耗時與 GAS 額度。
  • 單元測試同構保證：在 tests/courseCodeNormalization.test.js 中同時對前後端函式執行斷言，確保演算法規則 100% 同步！
