108 課綱課程代碼 1NF 正規化工程解析

解析教育部課程計畫平臺下載之 39 欄課綱寬表結構，透過第一正規化（1NF）數學展開、全數科目保留與字典快速映射，構建高效能標準課程資料庫。

1 為什麼需要 1NF（第一正規化）？

在教育部課程計畫平臺（全國高級中等學校課程計畫平臺）下載的 108 課綱課程代碼表中，為便於人工排版檢視，採用了多維度混合的橫向「寬表（Wide Table）」結構：

  • 單一資料列橫向包含了高一、高二、高三共六個學期的開課學分、時數與開課方式。
  • 欄位中同時包含了入學年、一年級學年、二年級學年、三年級學年。

這種寬表結構在資料庫檢索、排序與關聯時具有極大缺點：無法以單一條件篩選特定學期開課科目，必須寫複雜的多條件 OR 判斷。藉由第一正規化（1NF，First Normal Form）將六學期的重疊維度消除，轉為單一學期單一列的扁平化紀錄：

原始 39 欄寬表 1 列橫跨三年六學期
全數納入保留 全屬性代碼完整匯入
六學期展開 僅保留學分或時數 > 0
14 欄標準 1NF 單一學年/學期/年級索引

2 教育部課程計畫平臺 39 欄原始寬表欄位剖析

原始檔案具備以下 39 個欄位（0-based 索引 0 至 38）：

欄位範圍 欄位名稱 代表意義與用途
0 ~ 4 課程代碼、六學期開課學分、科目名稱、學生入學年、校代碼 課程基本身分與入學年標識。
5 ~ 11 課程類型、群別、科別、班群、課程類別、開課方式、科目屬性 代碼化屬性（如群別 23、科別 305、屬性 3）。
12 ~ 15 領域名稱、科目名稱代碼、科目代號、必選修 教育部課綱編碼資訊。
16 ~ 18 學生一、二、三年級學年 計算各年級修課當時之實際開課學年度（如 114、115、116）。
19 ~ 24 一上～三下開課學分（共 6 欄） 各學期實際授予學分數（判斷當期是否有開課之主依據）。
25 ~ 30 一上～三下開課時數（共 6 欄） 各學期每週實際上課節數。
31 ~ 36 一上～三下開課方式（共 6 欄） 各學期個別開課方式（若為空則退回第 10 欄預設開課方式）。
37 ~ 38 授課學期學分節數、課程屬性 統計與備註欄位。

3 108 課綱 23 碼課程代碼結構全解析

依據教育部國民及學前教育署 111 年 11 月 18 日臺教國署高字第 1110159457 號函公告修訂之《高級中等學校課程計畫資料交換規格及課程代碼介接規範》（詳見本專案 官方介接規範 PDF），全國各高中職開課清冊中的每一門課程均具備一組全國唯一的 23 碼固定長度課程代碼。該代碼於各校課程計畫經主管機關備查通過後即編定，一經編定就不再異動，具備絕對唯一性與不可變性。

💡 官方資料交換中的學分節數格式（六碼字串）：
在交換規格中，授課學期學分節數由 6 碼分別對應 1~6 學期（如 220000 表示一上與一下各開設 2 學分）。其中 0 表示無授課、Z 表示有授課但 0 學分、A~I 表示 1~9 學分對開（如 2B0000 表示一上 2 學分、一下與其對開 2 學分），而 R~T 則代表採計 10~12 學分。

4 屬性處理策略：全數課程代碼完整匯入

本專案設計為通用全端範本，為確保課程資料庫之完整性與通用查詢需求，全數匯入所有課程代碼，不剔除任何科目：

subjectCodeTransformer.js 
/** 科目屬性排除名單（本專案全數匯入，不剔除任何科目） */
const EXCLUDED_SUBJECT_ATTRIBUTES = [];

function isExcludedCourseRow(row) {
  if (!Array.isArray(row)) return false;
  if (EXCLUDED_SUBJECT_ATTRIBUTES.length === 0) return false;
  const attr = row[11] === null || row[11] === undefined ? "" : String(row[11]).trim();
  return EXCLUDED_SUBJECT_ATTRIBUTES.indexOf(attr) !== -1;
}
屬性代碼 屬性名稱 納入說明
"0" 不分屬性 包含週會、班會、社團活動或每週彈性學習時間等，於各學期有開課學分或時數時全數納入展開與索引。
"6" 特殊需求領域 包含特教或個別化教育計畫（IEP）之輔助課程，完整保留於正規化課程資料庫中，供全校性查詢。
"1" ~ "5" 一般/專業/實習/專題科目 常規學科與實習專業科目，全數正常展開並轉換為中文對照名稱。

5 展開演算法與數學映射關係

單一列 39 欄資料會經由迴圈 s = 0 ~ 5 檢驗六個學期：

subjectCodeTransformer.js (expandCourseRow) 
for (let s = 0; s < 6; s++) {
  const credits = Number(row[19 + s] || 0);
  const hours = Number(row[25 + s] || 0);

  // 1. 僅展開「學分 > 0 或時數 > 0」之實質開課學期
  if (!(credits > 0 || hours > 0)) continue;

  // 2. 年級索引 (0: 高一, 1: 高二, 2: 高三)
  const gradeIndex = Math.floor(s / 2);

  // 3. 開課學年：對應第 16 + gradeIndex 欄
  const academicYear = String(row[16 + gradeIndex] || "").trim();

  // 4. 開課學期：(s % 2) + 1 (1: 上學期, 2: 下學期)
  const semester = String((s % 2) + 1);

  // 5. 開課方式：優先取第 31 + s 欄，空值退回第 10 欄
  const semesterOpenWay = row[31 + s] || row[10];

  // 組裝 14 欄標準紀錄...
}

7 前後端同構運算設計 (Isomorphic Design)

傳統系統常在上傳檔案後整份丟給後端 GAS 運算，但 GAS 有單次請求時間與記憶體限制。本範本採用前後端同構設計：

  • 前端 ([courseData.js](file:///home/cookeyholder/Projects/GAS-Course-Web-Template/webapp/js/courseData.js))：使用 SheetJS 在用戶瀏覽器內完成解析與 1NF 展開，即時呈現「原始筆數」、「排除筆數」與「展開筆數」統計卡片，使用者確認無誤後才發送。
  • 後端 ([subjectCodeTransformer.js](file:///home/cookeyholder/Projects/GAS-Course-Web-Template/subjectCodeTransformer.js))：接收已預先展開之陣列，以每批 5000 筆快速寫入試算表，節省 90% 的後端運算耗時與 GAS 額度。
  • 單元測試同構保證：在 tests/courseCodeNormalization.test.js 中同時對前後端函式執行斷言，確保演算法規則 100% 同步！
