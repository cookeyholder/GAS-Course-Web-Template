Google 帳號登入 (GIS) 詳細設定教學

完整涵蓋 Google Cloud Console 憑證建立、已授權來源設定、範本端配置，以及本地端離線與即時測試方案。

1 GIS 登入機制原理

Google Identity Services (GIS) 是 Google 推出的新一代身分驗證客戶端程式庫（SDK 網址為 https://accounts.google.com/gsi/client）。

在 GAS-Course-Web-Template 中，登入流程具備以下防護與容錯設計：

1. 載入 GIS 前端動態載入 gsi/client 函式庫
2. Google 登入按鈕 用戶點擊並登入，回傳 ID Token (JWT)
3. 後端驗證 GAS 呼叫 tokeninfo 驗證簽章與發行者
4. 發放 Session 快取 6 小時 Token，前端存入 LocalStorage
🌟 多重備援機制：若尚未申請 Google Cloud OAuth Client ID，系統支援「Google Workspace 網域登入」（直接以 Session.getActiveUser() 辨識身分，無須彈跳 OAuth 視窗）；本地測試時更支援 ?mock=true 零設定離線模式！

2 Google Cloud Console 詳細設定步驟

要讓使用者的瀏覽器能順利顯示 Google 登入按鈕並通過身分驗證，必須於 Google Cloud Console 建立一組專屬的 OAuth 2.0 用戶端 ID。

步驟 2.1：建立或選取 Google Cloud 專案

  1. 前往 Google Cloud Console 並以您的 Google 帳號登入。
  2. 在頂部導覽列點選專案下拉選單，點擊「新增專案」（或選取現有專案）。
  3. 輸入專案名稱（例如：My-GAS-Web-System），點擊「建立」。

步驟 2.2：設定 OAuth 同意畫面 (OAuth Consent Screen)

  1. 由左側選單進入「API 和服務」→「OAuth 同意畫面」。
  2. User Type（使用者類型）：
    • 內部 (Internal)（推薦，學校或企業 Workspace 網域）：僅限本網域信箱登入，無須 Google 審查即可直接正式上線。
    • 外部 (External)（個人 Gmail 帳號）：若選取外部，在發布前需於「測試使用者」清單加入允許登入的 Gmail。
  3. 應用程式資訊：填入應用程式名稱（如 課程代碼管理系統）與使用者支援電子郵件。
  4. 範圍 (Scopes)：點擊「新增或移除範圍」，勾選基礎三項即可： .../auth/userinfo.email、 .../auth/userinfo.profile、 openid。
  5. 完成後點擊「儲存並繼續」。

步驟 2.3：建立「OAuth 用戶端 ID」憑證

  1. 由左側選單進入「API 和服務」→「憑證」。
  2. 點擊頂部「＋ 建立憑證」→ 選取「OAuth 用戶端 ID」。
  3. 應用程式類型選取：「網頁應用程式 (Web application)」。
  4. 名稱可自訂（例如：GAS Web Client）。
  5. 已授權的 JavaScript 來源 (Authorized JavaScript origins)：
    供 GIS 前端登入彈窗或 One Tap 使用，請填入：
    已授權的 JavaScript 來源（請逐筆新增）
    https://script.google.com
http://localhost
http://localhost:8080
http://127.0.0.1:8080
    ⚠️ 重要警示：絕對不要填寫 googleusercontent.com！
    Google Cloud Console 會將 googleusercontent.com 判定為禁止網域，若嘗試加入會直接噴出紅字錯誤：「來源無效：使用的網域遭到禁止 (Invalid Origin: URIs cannot contain googleusercontent.com)」。
    線上 Web App 環境只需要填入 https://script.google.com 即可！
  6. 已授權的重新導向 URI (Authorized redirect URIs)（供跳轉或備援登入使用）：
    請填入您的 Web App 正式部署網址：
    已授權的重新導向 URI 範例
    https://script.google.com/macros/s/{DEPLOYMENT_ID}/exec
https://script.google.com
    💡 Google Workspace 學校或企業網域特別提醒：
    若您的 Google 帳號屬於專屬網域（例如 @ksvs.kh.edu.tw），Web App 的實際執行網址會包含網域名稱（例如 https://script.google.com/a/ksvs.kh.edu.tw/macros/s/{DEPLOYMENT_ID}/exec）。
    請務必將此網域專屬網址也加入「已授權的重新導向 URI」，否則跳轉登入時會出現 錯誤 400：redirect_uri_mismatch。
  7. 點擊「建立」。
  8. 在彈出的視窗中，複製並保存「您的用戶端 ID」（格式為：xxxxxxxxxxxx-xxxxxxxxxxxxxxxx.apps.googleusercontent.com）。
⚠️ 安全性限制提醒：Google GIS 安全協定禁止直接在 file:// 協定下使用 OAuth Client ID。在本地端測試時，請透過本機 HTTP 伺服器或使用本範本內建的 Mock 模式。

3 範本端 Client ID 配置方式

取得 Client ID 後，您可以透過以下任一途徑填入專案中：

方式 A：透過 Web App 設定頁籤（最直覺）

  1. 以管理員身分登入 Web App。
  2. 進入「系統設定與授權」頁籤。
  3. 於「Google OAuth 2.0 Client ID」欄位貼上剛才取得的 ID。
  4. 點擊「儲存系統設定」即可立即生效！

方式 B：直接填入 Google 試算表

  1. 開啟關聯的 Google 試算表。
  2. 切換至「系統設定與授權」工作表。
  3. 找到 B5 儲存格（設定項目「OAuth Client ID」對應的值），直接貼上該字串即可。

方式 C：程式碼預設值（建置新專案時）

若希望在初始化資料庫時就帶有預設 Client ID，可修改 databaseInitializer.js：

databaseInitializer.js (約第 25 行)
const DEFAULT_SYSTEM_PARAMS = [
  ["設定項目", "設定數值"],
  ["學年度", "114"],
  ["學期", "1"],
  ["系統名稱", "Google Apps Script 應用程式範本"],
  ["OAuth Client ID", "您的-CLIENT-ID.apps.googleusercontent.com"], // 👈 填入您的 Client ID
  ["OAuth Client Secret", ""],
  ["登入白名單限制啟用", "false"]
];

4 本地端開發與測試方式

在本機電腦開發前端樣式與互動時，有三種測試登入的解決方案：

方案 1：Mock 模式（零設定、離線秒開，推薦日常開發）

專案內建 webapp/js/mock.js 模擬器，完全不需要任何 Google Cloud 設定與網路連線：

  1. 在終端機打包前端：npm run build:webapp
  2. 直接以瀏覽器開啟根目錄的 index.html，並在網址後方加上 ?mock=true：
    file:///home/cookeyholder/Projects/GAS-Course-Web-Template/index.html?mock=true
  3. 在登入畫面點擊「🧪 本地測試身分登入 (Mock Mode)」，即可一鍵進入系統！

方案 2：本機 HTTP 伺服器 + 真實 GIS 登入（驗證完整 OAuth）

若希望在本地端以真實的 Google 帳號點擊登入按鈕：

  1. 確認步驟 2.3 的「已授權的 JavaScript 來源」已加入 http://localhost:8080。
  2. 在專案根目錄啟動簡易 HTTP 伺服器：
    終端機指令 (任選一種)
    # 使用 Python 3 內建伺服器
python3 -m http.server 8080

# 或使用 npx serve
npx serve . -p 8080
  3. 在瀏覽器中開啟：http://localhost:8080/index.html。
  4. 此時 Google 登入按鈕即可正常渲染，點擊即可完成 Google 登入！

方案 3：Google Workspace 網域免彈窗登入

當專案部署至 Google Apps Script 後，若同處於教育機構或企業 Google Workspace 網域：

  1. 使用者開啟 Web App 網址。
  2. 直接點擊「🏢 使用目前 Google Workspace 帳號登入」。
  3. 後端直接藉由 Session.getActiveUser().getEmail() 取得登入者身分，完全不需 OAuth Client ID。

5 後端憑證驗證與安全 Session 快取

在 webApi.js 中，登入流程嚴格遵循安全性檢驗標準：

5.1 憑證校驗 (Token Verification)

後端透過 UrlFetchApp 呼叫 Google 官方端點檢驗 JWT 簽名：

webApi.js (verifyGoogleIdToken)
function verifyGoogleIdToken(idToken, expectedClientId) {
  const url = "https://oauth2.googleapis.com/tokeninfo?id_token=" + encodeURIComponent(idToken);
  const resp = UrlFetchApp.fetch(url, { muteHttpExceptions: true });
  const info = JSON.parse(resp.getContentText());

  // 1. 驗證是否包含 Email
  if (!info.email) throw new Error("無效的憑證");

  // 2. 驗證受眾（aud）是否與專案的 Client ID 一致（防止跨 App 偽造）
  if (expectedClientId && info.aud !== expectedClientId) {
    throw new Error("Client ID 不相符");
  }

  return { email: info.email.toLowerCase(), name: info.name };
}

5.2 Session 快取機制 (CacheService)

驗證通過後，後端產生一組加密隨機 Token（gas_時間_隨機碼），儲存至 CacheService.getScriptCache()，有效時間設為 6 小時（21,600 秒）。前端後續的所有 API 請求均以 POST + text/plain 攜帶此 Token，兼顧安全性與流暢體驗。

6 常見錯誤與排解指南

錯誤現象 / 代碼常見原因解決方案
來源無效：使用的網域遭到禁止
(Invalid Origin)		 在 Google Cloud Console 的「已授權 JavaScript 來源」填入了 *.googleusercontent.com。Google 判定該網域為使用者內容代管網域，強制禁止加入。 請將 googleusercontent.com 移除，線上環境只需保留 https://script.google.com 即可。
origin_mismatch 當前網頁的 Origin（例如 http://localhost:8080 或 https://script.google.com）未加入 Google Cloud Console 憑證的「已授權 JavaScript 來源」。 請返回 Google Cloud Console 的憑證設定，在「已授權的 JavaScript 來源」完整填入當前網址的協定與網域名稱（不含子路徑）。
按鈕沒有出現，或控制台顯示 file:// not supported 直接在檔案總管雙擊以 file:/// 協定開啟 HTML。GIS 函式庫嚴格禁止 file://。 請於網址加上 ?mock=true 開啟模擬測試，或以 python3 -m http.server 8080 啟動本機伺服器。
not_whitelisted 系統設定中勾選了「嚴格啟用白名單限制」，但該登入帳號未列於「系統設定與授權」工作表的 D 欄名單中。 請請系統管理員於「系統設定與授權」工作表將該 Email 加入授權白名單，並將啟用狀態設為「是」。
client_id_mismatch 前端送出的憑證 aud 與試算表中儲存的 OAuth Client ID 不一致。 請確認試算表 B5 儲存格與 Google Cloud Console 中的 Client ID 字串完全一致（注意不可有前後多餘空白）。
