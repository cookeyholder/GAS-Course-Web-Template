Google 帳號登入（GIS）雙軌整合與設定教學

適用於 GAS-Course-Web-Template：涵蓋 Google Identity Services、GAS ActiveUser/AccountChooser、OAuth 授權碼回呼、網域限制與常見排除。 · 返回技術手冊索引

1. 概述與雙軌登入

本範本支援多種登入情境，前端與後端會依執行環境自動選擇適當流程，並維持同一套 Session 與權限檢查機制。

情境 流程 前置條件
GAS 容器內 透過 google.script.run 呼叫 loginWithActiveUser，並可搭配 Google AccountChooser / ?switch=1 切換帳號。 使用者需以可存取該 Web App 的 Google 帳號登入瀏覽器；可選填 Client ID/Secret 與網域限制。
一般網頁 / 本機服務 載入 Google Identity Services（GIS）憑證按鈕，前端取得 ID Token 後送至後端 login 驗證。 需於 Google Cloud 設定 OAuth 用戶端與已授權 JavaScript 來源，並在系統設定填入 Client ID。
OAuth 授權碼回呼（備援） 後端 doGet 接收 ?code= 回呼，交換權杖並驗證 id_token 後注入 INITIAL_AUTH。 需同時設定 Client ID、Client Secret 與正確的重新導向 URI（Web App /exec 網址）。
RPC 優先：前端 API 客戶端在 GAS HtmlService 容器內優先使用 google.script.run.executeWebApi，一般環境才改用 fetch 備援，且 POST 一律使用 Content-Type: text/plain;charset=utf-8 以避免 CORS 預檢。

2. 前置條件

  • 已建立並部署 Google Apps Script Web App（建議執行身分為「我」，存取權依需求設定）。
  • 已於試算表執行「初始化資料庫工作表」，產生「系統設定與授權」等工作表。
  • 若要使用 GIS 憑證按鈕或授權碼回呼，需具備 Google Cloud 專案與 OAuth 2.0 用戶端憑證。
首次登入防鎖：登入入口預設不開通管理員；只有當呼叫鏈明確標記 allowBootstrap、且授權白名單確實為空時，第一位成功驗證的 Google 帳號才會建立為系統管理員。寫入集中在短鎖臨界區並再次檢查白名單，避免多位登入者併發搶占或覆寫既有設定。

3. 登入流程說明

3.1 GAS 容器：ActiveUser 與帳號切換

  1. 前端偵測到 google.script.run 可用時，登入按鈕會導向 AccountChooser（可帶 hd 網域提示）。
  2. 回到 Web App 並帶入 ?switch=1 時，前端會清除本地 Session 後呼叫 loginWithActiveUser。
  3. 後端以 Session.getActiveUser().getEmail() 取得帳號，檢查網域限制與授權白名單後建立 Session。

3.2 一般環境：GIS ID Token

  1. 前端載入 https://accounts.google.com/gsi/client 並以 Client ID 初始化按鈕。
  2. 使用者登入後取得 credential（ID Token），前端呼叫後端 login。
  3. 後端透過 tokeninfo 驗證簽章、發行者（iss）、受眾（aud）、email_verified 與允許網域後建立 Session。

3.3 授權碼回呼（OAuth Code Callback）

當後端收到 GET ?code=... 且已設定 Client Secret 時，會向 Google 交換權杖並驗證回傳的 id_token；成功後將登入結果注入頁面模板的 INITIAL_AUTH，前端啟動時優先套用，並清理網址查詢參數。

使用時機：此流程可作為需要伺服器端交換授權碼的備援路徑；實際可用性仍取決於 Google OAuth 設定與 Web App 部署網址是否完全一致。

3.4 OAuth state nonce 一次性驗證

發起授權碼流程時，前端產生不可預測的 nonce，連同重新導向 URI 存入 sessionStorage，並將兩者序列化為 state 參數送出。回呼時後端會解析 state，確認 nonce 存在且尚未使用（以 CacheService 一次性消耗，預設 10 分鐘有效），並比對 redirectUri 與設定值；重放、格式異常或導向 URI 不符即拒絕登入。

與寫入相關的外部 HTTP（授權碼交換權杖、ID Token 驗證）會在取得 LockService 之前完成，僅 doGet 回呼寫入鏈（state 驗證、建立 Session、必要時開通管理員）進入鎖定臨界區，縮短臨界區並降低逾時風險。

4. Google Cloud 設定

4.1 OAuth 同意畫面與用戶端

  1. 於 Google Cloud Console 建立或選取專案，設定 OAuth 同意畫面。
  2. 建立憑證 → OAuth 用戶端 ID → 應用程式類型選「網頁應用程式」。
  3. 將取得的 Client ID 與（視需要）Client Secret 填入試算表或系統設定頁面。

4.2 已授權的 JavaScript 來源

  • 正式 GAS Web App：https://script.google.com
  • 本機測試（若以本機伺服器載入前端）：http://localhost、http://localhost:8080 等實際來源
重要：請勿將 https://*.googleusercontent.com 加入「已授權的 JavaScript 來源」。該網域無法作為 GIS 按鈕來源設定，且容易造成設定錯誤。

4.3 已授權的重新導向 URI（僅授權碼回呼需要）

  • Web App 正式部署網址：https://script.google.com/macros/s/{DEPLOYMENT_ID}/exec
  • 若使用 Workspace 網域專屬入口，亦需新增對應的 /a/{DOMAIN}/macros/s/{DEPLOYMENT_ID}/exec URI。

5. 範本系統設定

系統參數儲存於試算表「系統設定與授權」工作表，可由管理員在「系統設定與授權」頁籤維護：

設定項目 說明
OAuth Client ID GIS 憑證按鈕與 ID Token aud 驗證使用。
OAuth Client Secret 授權碼回呼交換權杖時使用（選填，依部署需求）。
Google 登入允許網域 選填，例如 example.edu.tw；設定後僅允許該網域帳號登入。
登入白名單限制啟用 啟用後僅白名單內啟用帳號可登入；未啟用時依預設策略與首次管理員規則處理。
授權白名單 管理 Email、姓名/職稱、角色（admin/staff/viewer）與啟用狀態。 
// 後端公開設定（getPublicConfig）會提供前端顯示所需欄位：

  "ok": true,
  "systemName": "…",
  "schoolYear": "114",
  "semester": "1",
  "clientId": "…apps.googleusercontent.com",
  "hasClientSecret": true,
  "allowedDomain": "example.edu.tw",
  "activeEmail": "user@example.edu.tw",
  "webAppUrl": "https://script.google.com/macros/s/.../exec"

6. Session 與 CSRF 安全

  • 登入成功後後端核發 Session Token（儲存於 CacheService，預設 6 小時），並同時核發 CSRF Token。
  • 前端 API 客戶端會保存並在後續請求自動夾帶 token 與 csrfToken。
  • 寫入型 action（如匯入課程、儲存設定、儲存白名單、登出）會驗證 CSRF Token；驗證失敗需重新整理頁面後再試。
  • getPublicConfig、ping 為公開唯讀；login、loginWithActiveUser 為公開登入入口。
權限控管：後端以 RBAC 角色權限矩陣限制可呼叫的 action；前端僅負責介面呈現，實際授權仍以後端驗證為準。所有 action、公開／寫入／鎖定清單與角色權限皆由 actionRegistry.js 單一登錄來源產生，未登錄的 action 會被路由層直接拒絕。
API 端點白名單：前端僅接受同源、明確設定的 GAS_WEBAPP_URL、正規 GAS Web App 網址與本機開發端點；不受信任的 ?api= 參數會被忽略，避免 Session／CSRF Token 外送至其他站台。允許登入網域會正規化為小寫後比對，大小寫不一致不會造成誤判。

7. 本機 Mock 測試

在本機開啟開發原始檔 webapp/index.html 並加上 ?mock=true，即可啟用前端 Mock 模擬器： 

file:///.../webapp/index.html?mock=true
# 或
http://localhost:8080/webapp/index.html?mock=true
  • 可模擬公開設定、登入、Session 還原、課程代碼篩選／分頁與系統設定／白名單操作。
  • Mock 僅存在於前端攔截層，不會在後端建立測試後門。
  • 正式建置產物（根目錄 index.html）會注入 MEA_PRODUCTION_BUILD 並忽略 ?mock=true，避免部署後仍可切換假資料。
  • 適合驗證介面流程、樣式與欄位互動；正式部署前仍需在 GAS 環境完成整合驗證。

8. 常見錯誤與排除

狀況 可能原因 排除建議
Google 登入按鈕未顯示或初始化失敗 未設定 Client ID、JavaScript 來源不符、或瀏覽器阻擋第三方腳本 確認系統設定中的 Client ID；檢查 Google Cloud「已授權的 JavaScript 來源」；於本機可改用 ?mock=true 測試介面。
顯示「來源無效」或來源設定遭拒 將 googleusercontent.com 填入已授權來源 移除該來源；正式環境使用 https://script.google.com，本機使用實際 localhost 來源。
登入失敗：網域不被允許 「Google 登入允許網域」已設定且帳號網域不符 確認設定值（不含 @）與使用者帳號網域一致，或清空限制後再試。
CSRF Token 驗證失敗 頁面長時間未操作、Session 更新後舊頁面仍持有舊 token、或多分頁狀態不一致 重新整理頁面以取得最新 Session/CSRF，並避免在過期頁面送出寫入操作。
授權碼回呼失敗 未設定 Client Secret、重新導向 URI 不一致、OAuth state nonce 已使用或過期、或 Web App 網址無法解析 確認 Client ID/Secret 與重新導向 URI 完全一致；若顯示 nonce 相關錯誤，請重新發起登入流程；檢查部署網址（含網域路徑）並重新部署新版。
顯示未授權 白名單限制啟用但帳號未在清單中、或帳號已停用 請管理員檢查「授權白名單成員清單」與啟用狀態；白名單為空且登入鏈明確允許開通時，第一位成功登入者才會成為管理員。
