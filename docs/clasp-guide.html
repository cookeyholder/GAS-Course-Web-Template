Google clasp 安裝、同步與版本化部署完全指南

擺脫瀏覽器線上編輯器的限制！使用 Google 官方命令列工具 clasp，在本機享受 VS Code、Git 版本控制、自動打包與專業發布工作流。

1 認識 clasp 與核心優勢

clasp（Command Line Apps Script Projects） 是 Google 官方專為 Google Apps Script 開發者設計的 CLI 工具。

傳統在瀏覽器線上 Apps Script 編輯器中寫程式常面臨以下痛點：

  • 無法使用 Git 進行分支管理與 Commit 歷程追蹤。
  • 無法拆分模組化 CSS/JS 檔案（線上無法使用現代前端打包腳本）。
  • 沒有本機 IDE（如 VS Code）的智慧補全、快捷鍵與自動格式化。

透過 clasp，您可以將雲端的 Apps Script 專案視為本地檔案庫進行雙向同步：

本地端開發 VS Code + Git + npm
自動建置打包 build-webapp.js 合併資源
clasp push 上傳至 Google 雲端專案
clasp deploy 建立不可變版本與網址發布

2 事前必要設定：啟用 Google Apps Script API

⚠️ 關鍵步驟：首次使用 clasp 之前，必須手動在 Google 帳號中開啟「Google Apps Script API」，否則執行任何指令皆會回傳 User has not enabled the Apps Script API 錯誤！

啟用步驟如下：

  1. 使用您的瀏覽器開啟：Google Apps Script 使用者設定頁面。
  2. 在「Google Apps Script API」選項處，將開關切換為「開啟 (ON)」。

3 安裝與帳號登入授權

3.1 安裝方式

本專案 package.json 已將 @google/clasp 列為開發相依套件，您可以選擇全域安裝或透過專案執行：

終端機安裝指令 
# 方式 A：全域安裝（推薦，任何目錄皆可直接呼叫 clasp）
npm install -g @google/clasp

# 方式 B：僅使用專案內建版（前綴加上 npx）
npx clasp --version

3.2 登入 Google 帳號

執行登入指令，系統會自動開啟預設瀏覽器要求您授予 OAuth 存取權限：

登入指令 
clasp login
  1. 在開啟的 Google 登入網頁中，選擇您擁有該 Apps Script / 試算表權限的帳號。
  2. 點擊「允許」授權 clasp 管理您的 Apps Script 專案。
  3. 授權成功後，瀏覽器會顯示 Logged in! You may close this page.。
  4. clasp 會將認證憑證儲存於本機家目錄的 ~/.clasprc.json。

隨時可透過以下指令確認目前的登入身分：

clasp login --status

4 建立與複製專案 (clone / create)

情境 A：複製現有試算表的 Apps Script 專案 (clone)

如果您已經有一張現成的 Google 試算表，且裡面已有 Apps Script：

  1. 開啟該試算表，點選「擴充功能」→「Apps Script」。
  2. 點選左側選單的「專案設定（齒輪圖示）」。
  3. 找到「指令碼 ID (Script ID)」（格式類似：1fM5R5gHxR3zm8hGa9GtgVPMuk2U...）並複製。
  4. 在終端機執行 clasp clone：
    終端機指令 
    # 複製至新資料夾
clasp clone <您的 Script ID> --rootDir .

情境 B：綁定至本範本專案 (.clasp.json)

在 GAS-Course-Web-Template 目錄中，已經為您備妥設定檔範本：

  1. 複製範本設定檔： 
    cp .clasp.json.example .clasp.json
  2. 打開 .clasp.json，將 scriptId 替換為實際的專案 ID： 
    {
  "scriptId": "貼上您的指令碼 ID",
  "rootDir": "."
}

情境 C：由本機全新建立專案 (create)

# 建立綁定至指定試算表容器的專案
clasp create --title "課程管理 Web App" --type sheets --parentId "<試算表檔案 ID>"

5 核心設定檔解析 (.clasp.json 與 .claspignore)

5.1 .clasp.json (專案設定)

設定屬性 預設值 用途說明
scriptId （必填） 雲端 Google Apps Script 專案唯一代碼。
rootDir "." 程式碼根目錄，指定 clasp 該監聽與推送哪個路徑。
skipSubdirectories false 是否跳過子目錄。

5.2 .claspignore (推送過濾清單，極其重要！)

Google Apps Script 不支援直接上傳任意目錄（如 node_modules/、webapp/），否則會報錯或檔案混亂。
本專案的 .claspignore 採用負向白名單（Negative Whitelist）機制：

.claspignore 
# 1. 預設忽略所有檔案與子目錄
**

# 2. 僅允許推送後端根目錄腳本、Manifest 與打包後的單一 index.html
!appsscript.json
!*.js
!index.html
✨ 原理：您在 webapp/ 中的多個 CSS/JS 原始碼檔案會經由打包腳本內嵌至根目錄的 index.html。因此 clasp 只需要推送根目錄的 *.js 與 index.html 即可！

6 雙向同步工作流：push 與 pull

6.1 本機推送至雲端 (push)

每次修改完前端或後端程式碼，務必先打包再推送。專案的 npm run push 已自動幫您串接好：

終端機指令 
# 一鍵打包並推送（推薦日常使用）
npm run push

# 等同於依序執行：
# 1. npm run build:webapp
# 2. clasp push

6.2 即時變更監聽與自動推送 (watch)

在頻繁修改程式碼時，可以開啟監聽模式：

npm run watch
# 或：clasp push --watch

只要檔案一存檔，clasp 就會自動將異動同步至雲端，免去手動輸入指令的繁瑣。

6.3 雲端抓取至本機 (pull)

如果有人在網頁端編輯器修改了程式碼，可使用 pull 拉回本機：

npm run pull
# 或：clasp pull

7 版本化部署 (Version & Deploy)

在 Google Apps Script 中，Web App 是基於「部署（Deployment）」發布的。若您只執行了 clasp push，使用者瀏覽到的 Web App 仍然是上一次發布的舊版本，必須進行「部署更新」。

7.1 查看現有部署與版本

終端機指令 
# 查看目前所有的部署（含 Deployment ID 與 Web App 網址）
clasp deployments

# 查看程式碼發布歷程版本
clasp version

7.2 建立不可變版本快照 (Version)

為目前的程式碼記錄一個不可變的發布版本：

clasp version "v1.0.0 正式版上線"

7.3 建立新部署 (全新網址)

clasp deploy --description "正式生產環境部署 v1.0.0"

執行後會顯示該次部署的 Deployment ID 以及對應的 Web App 執行網址。

7.4 更新既有部署（保持固定 Web App 網址，最佳實務！）

🌟 最佳實務：為了避免每次發布都產生新的網址导致使用者書籤失效，請使用 -i <deploymentId> 覆蓋既有部署，網址將永遠保持固定！
更新既有部署指令 
# 1. 先用 clasp deployments 找到目前的 Deployment ID（以 AKfycb... 開頭）
clasp deployments

# 2. 指定該 Deployment ID 進行更新
clasp deploy -i <您的 Deployment ID> -d "更新：修正課程搜尋分頁問題"

7.5 一鍵部署快捷指令

在專案中，您也可以直接執行（預設會先建置並推送，再建立新部署）：

npm run deploy

若要更新既有部署以保持 Web App 網址固定，可指定 Deployment ID：

CLASP_DEPLOYMENT_ID=<您的 Deployment ID> npm run deploy
# 或
node scripts/deploy.js -i <您的 Deployment ID> -d "版本說明"

8 常見問題與除錯指令

8.1 快速開啟專案工具

# 直接以瀏覽器開啟雲端 Apps Script 編輯器
clasp open

# 直接開啟目前發布的 Web App 網頁
clasp open --webapp

8.2 檢視後端執行記錄 (StackDriver Logs)

# 查看最新執行的 console.log 與錯誤記錄
clasp logs

# 即時持續監聽記錄輸出
clasp logs --watch

8.3 常見錯誤速查表

錯誤訊息 成因 解決方法
User has not enabled the Apps Script API Google 帳號中未開啟 Apps Script API 開關。 至 使用者設定頁 將開關切換為 ON。
Could not find .clasp.json 尚未建立專案設定檔或路徑錯誤。 執行 cp .clasp.json.example .clasp.json 並填入 Script ID。
Invalid JSON in .clasp.json 設定檔格式有逗號錯誤或引號缺失。 檢查 .clasp.json 語法，確保符合標準 JSON 格式。
推送後網頁程式碼沒有改變 只執行了 push，未更新部署（Deployment）。 執行 clasp deploy -i <deploymentId> 重新發布新版。
