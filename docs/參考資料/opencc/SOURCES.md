# OpenCC 來源與實測紀錄

本文件記錄本專案移植 OpenCC 語言檢查能力的套件來源、版本、實測結果與設計取捨。為避免工具自身命中硬閘門，所有簡體字與中國用語皆以 `\uXXXX` 跳脫表示；下表「輸入」「輸出」欄位中的 `\uXXXX` 型式即為原始碼中所見的字元序列。

## 套件來源

| 項目     | 內容                                                                                   |
| -------- | -------------------------------------------------------------------------------------- |
| 套件名稱 | `opencc`                                                                               |
| 精確版本 | `1.4.2`（不使用插入符號或波浪符號範圍）                                                |
| 授權     | Apache-2.0                                                                             |
| 用途     | 僅供 Node 工具鏈使用，不進入 GAS 後端、前端原始檔或打包產物                            |
| 定位設定 | `s2tw.json`（字級，候選定位來源）                                                      |
| 建議設定 | `s2twp.json`（字級＋片語，慣用語建議來源）                                             |
| 解析器   | `@babel/parser` 精確版本 `7.29.15`，供契約字面值清冊之 AST 靜態解析                    |
| 移植來源 | `KSVS-Course-Information-Collector`，commit `81935296ea8cb2c4661438b3e92835e4cf2d27c8` |

來源專案以 Node 20、寬鬆覆蓋率與不同的指令名稱為前提，本專案依現行 Node 24、品質閘門與 `check:lang` 契約重新對應，故不直接複製其實作。

## 黃金案例

下表輸出以 Unicode 跳脫呈現，括號內為人工判讀說明。

| 輸入                           | `s2tw` 輸出            | `s2twp` 輸出                   |
| ------------------------------ | ---------------------- | ------------------------------ |
| `\u9879\u76ee`（簡體「項目」） | `\u9805\u76ee`（項目） | `\u5c08\u6848`（專案）         |
| `\u6570\u636e`（簡體「數據」） | `\u6578\u64da`（數據） | `\u8cc7\u6599`（資料）         |
| `\u6743\u9650`（簡體「權限」） | `\u6b0a\u9650`（權限） | `\u8a31\u53ef\u6b0a`（許可權） |
| `\u4ec5`（簡體「僅」）         | `\u50c5`（僅）         | `\u50c5`（僅）                 |

最後一列說明：既有精簡字集未收錄 `\u4ec5`，硬閘門不會紅燈，但 `s2tw` 仍有差異，故可被定位為候選。

## 正體不變與誤改對照

下列正體詞在 `s2tw` 下完全不變，因此不會產生候選；但 `s2twp` 會進行片語誤改，這正是「定位與建議必須分離」的實測依據。

| 正體輸入                               | `s2tw` | `s2twp`                                        |
| -------------------------------------- | ------ | ---------------------------------------------- |
| `\u9805\u76ee`（項目）                 | 不變   | `\u5c08\u6848`（專案）                         |
| `\u6578\u64da`（數據）                 | 不變   | `\u8cc7\u6599`（資料）                         |
| `\u8ab2\u7a0b\u4ee3\u78bc`（課程代碼） | 不變   | `\u8ab2\u7a0b\u7a0b\u5f0f\u78bc`（課程程式碼） |
| `\u6b0a\u9650`（權限）                 | 不變   | `\u8a31\u53ef\u6b0a`（許可權）                 |
| `\u5831\u544a\u9805\u76ee`（報告項目） | 不變   | `\u5831\u544a\u5c08\u6848`（報告專案）         |

因此工具規則為：`s2tw` 差異決定候選是否存在，`s2twp` 差異僅附加為建議選項，且必須由人工依上下文挑選並明確核准後才得寫入。

## 邊界案例

### 純正體慣用語

繁體「鼠標」（`\u9f20\u6a19`）在 `s2tw` 下不變，故永不產生候選；雖然 `s2twp` 可轉換為「滑鼠」（`\u6ed1\u9f20`），該建議不會出現。本工具不宣稱可自動處理純正體慣用語。

### 由正體字組成的中國用語違規

下列詞彙全由正體字組成，`s2tw` 對其無差異，故不進入 OpenCC 候選範圍，仍由硬閘門回報並由人工修正：

| 原文           | `s2tw` | `s2twp`                |
| -------------- | ------ | ---------------------- |
| `\u652f\u6301` | 不變   | `\u652f\u63f4`（支援） |
| `\u914d\u7f6e` | 不變   | 不變                   |
| `\u53bb\u91cd` | 不變   | 不變                   |
| `\u54c8\u5e0c` | 不變   | `\u96dc\u6e4a`（雜湊） |

CI 構件檢查須比對硬閘門違規數與候選數：當有違規但零候選且未降級時發出警告，避免形成「硬閘門紅燈、報告零候選」的假保險。

## 選用 AST 的理由

契約字面值清冊需要正確區分註解、字串與正則表達式，並排除豁免註解與以 Unicode 跳脫表示的負面字面值。`@babel/parser` 提供完整的 `StringLiteral` 與 `RegExpLiteral` 節點，可避免正規表達式誤收與註解誤判；版本精確鎖定 `7.29.15`，防止漂移改變清冊結果。

## 已知限制

- 整行位置移動不影響穩定識別碼，但同一行被重新格式化、前方插入相同字面值或上下文改變，都會使核准失效並要求重新核准。
- 工具版本升級若改變識別碼演算法，既有核准紀錄全數失效並標註 `ID_ALGORITHM_CHANGED`。
- 受保護清冊雙向收錄正體「項目」（`\u9805\u76ee`）與「專案」（`\u5c08\u6848`），用以保護候選原文位置；但 `\u9879\u76ee` 為真實簡體違規，人工核准寫入「專案」屬預期行為。
