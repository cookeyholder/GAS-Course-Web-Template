## ADDED Requirements

### Requirement: 系統設定與授權資料純轉換器（Pure System Data Codec）
後端系統設定（區塊 A）與授權白名單（區塊 B）之資料層轉換，其試算表二維矩陣與領域物件之間的解析、合併與格式序列化邏輯 MUST 抽離為獨立的純模組 `systemConfigCodec.js`。該模組 MUST 具備雙棲相容性（Node.js `module.exports` 與 GAS 全域），且不得含有任何 Google Apps Script 平台專屬全域依賴（如 `SpreadsheetApp`、`LockService`）或外部狀態。轉換邏輯 MUST NOT 修改或刪除任何傳入參數之屬性（禁止對輸入物件執行 `delete` 或就地變異傳入陣列）；在合併設定更新時，轉換函式 MUST 傳回全新建立的二維矩陣，並支援指定目標範圍大小自動補齊空白列，確保外層寫入時完全覆蓋既有區間以消除幽靈殘留列（Ghost Rows）。純轉換模組 MUST 具備獨立的單元測試，且測試過程 MUST NOT 建立或依賴任何試算表 Mock 物件。

#### Scenario: 解析系統設定二維矩陣為雙軌鍵值領域物件
- **WHEN** 提供包含中文鍵名、布林字串與網域字串的 A:B 二維矩陣（不論是否包含第一列表頭）
- **THEN** 純轉換函式傳回同時具備原始中文鍵（如 `學年度`、`系統名稱`）、自訂未知鍵與駝峰便捷鍵（如 `schoolYear`、`systemName`）之標準設定物件，且未修改原始二維矩陣

#### Scenario: 合併系統設定更新時不變異輸入參數並消除幽靈殘留列
- **WHEN** 傳入既有二維矩陣、包含部分新舊設定項目的 `updates` 物件，並指定目標範圍行數（如 29 行）
- **THEN** 函式傳回合併後的全新二維陣列（舊項目已更新、新項目已追加、不足行數已補齊空字串對），且傳入的 `updates` 物件屬性完全未被刪除或更動

#### Scenario: 解析與序列化白名單帳號矩陣保持雙向一致性
- **WHEN** 將 D:G 二維列陣列經由白名單純解析函式轉換為標準帳號物件陣列，再經由序列化函式轉回二維矩陣
- **THEN** 有效帳號的 Email（小寫 trim）、姓名、角色顯示名稱與啟用狀態（「是」／「否」）保持精確一致，且空白列與無效 Email 列已被過濾
