## Context

工作表名稱目前由 `gasRuntime.js` 的 `SHEET_COURSE_INDEX` 單一提供，初始化、寫入與查詢都讀取同一常數。更名常數值會讓既有試算表（工作表仍名為「正規化課程索引」）在初始化後出現新舊兩張工作表，查詢指向空的新表。詳見 proposal.md「Why」。

## Goals / Non-Goals

**Goals:**

- 讓工作表名稱與前端「課程代碼」術語一致。
- 既有試算表執行初始化時自動完成更名，不遺失資料。
- 重複初始化保持冪等。

**Non-Goals:**

- 不變更 14 欄表頭、1NF 展開規則或 API 契約。
- 不重新命名英文識別碼（`SHEET_COURSE_INDEX`、`COURSE_INDEX_WRITE_CHUNK_SIZE`）。
- 不回寫已封存的 OpenSpec 歷史紀錄。

## Decisions

### 以「更名」取代「建立新表並搬移資料」

`databaseInitializer.js` 的 `ensureCourseIndexSheet_` 改為三段判斷：新名稱已存在直接返回；否則檢查舊名稱，存在則呼叫 `setName` 更名；兩者都不存在才建立新表並寫入表頭。

- 優點：保留工作表格式、凍結列與既有資料，無需逐列搬移，也不會因大量資料逾時。
- 替代方案：建立新表後複製資料再刪舊表——資料量大時成本高且失敗難回滾，故不採用。

### 舊名稱常數由 gasRuntime 單一提供

在 `gasRuntime.js` 新增 `LEGACY_SHEET_COURSE_INDEX = "正規化課程索引"` 並匯出，初始化模組從同一來源取得。舊名稱只出現在遷移判斷，不用於讀寫目的，避免日後誤用。

- 替代方案：在初始化模組寫死字串——會形成第二個定義來源，違反既有單一來源原則。

### 前端文案採精確字串替換而非全面移除「108 課綱」

只改功能標題、拖曳區與頁籤說明的「課綱／課程索引」用詞；描述課綱標準本身的技術文件（23 碼結構、課綱寬表）保留原文。

- 優點：維持官方名詞的正確性，同時讓使用者操作區的術語一致。
- 替代方案：全面移除「108 課綱」——會讓技術文件失去標準依據語境。

### 建置產物由腳本產生

`index.html` 不手動編輯，統一執行 `npm run build:webapp` 重新內嵌，並以連續兩次建置的雜湊相同驗證一致性。

## Risks / Trade-offs

- [既有試算表未執行初始化前查詢會找不到新工作表] → 於 README 與交付說明標註須先執行「初始化資料庫工作表」；初始化具冪等性，可安全重複執行。
- [更名後新舊工作表同時存在] → 初始化先檢查新名稱，舊表保留但不使用；不自動刪除以降低資料遺失風險。
- [英文識別碼沿用舊語意] → 維持 API 與模組匯出相容，僅註解與文案更新。

## Migration Plan

1. 部署新版程式碼。
2. 在 Google 試算表執行「初始化資料庫工作表」工具列選單，觸發一次性更名。
3. 執行 `npm test` 與品質閘門，確認初始化與查詢正常。
4. 回滾：還原程式碼後再次初始化；工作表名稱為新值時查詢仍可運作，舊名稱不會被重建。
